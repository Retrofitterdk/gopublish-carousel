# Go:Publish Carousel

A carousel block for WordPress. Each slide can hold any blocks. The carousel is rendered on the server and built on native scrolling (CSS scroll snap), with a small script on the [Interactivity API](https://developer.wordpress.org/block-editor/reference-guides/interactivity-api/) for the buttons. No jQuery or third-party slider library.

- **Requires:** WordPress 6.8+, PHP 7.2+
- **License:** GPL-2.0-or-later
- **Changelog and user FAQ:** see [readme.txt](readme.txt)

## Features

- Slides (`gopublish/carousel-slide`) can contain any blocks.
- 1–6 slides visible at once, with a configurable number of slides to scroll.
- Optional cutoff effect: the last visible slide is partly shown.
- Separate slide width on mobile and tablet (follows the theme's viewport settings; default up to 782 px).
- Native scrolling: swipe, trackpad, keyboard and momentum are handled by the browser, snapping to the start of a slide.
- Previous/next buttons, with optional rewinding at the ends (*Rewind at the end*).
- Navigation is hidden when all slides fit in view.
- Block spacing sets the gap between slides, per viewport in WordPress 7.1.
- Right-to-left support.
- The editor shows the carousel as on the front end (one scrollable row with the real widths, gap and arrows), with a "Show all slides" grid view and an "Add slide" toolbar button.
- Wide/full alignment, spacing and minimum height support.
- Accessible, following the [W3C carousel pattern](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/) (see below).
- Translation-ready; Danish included.

## Installation

**From a zip:** upload it under Plugins → Add New → Upload Plugin, then activate it.

**From source:**

```bash
git clone https://github.com/Retrofitterdk/gopublish-carousel.git
cd gopublish-carousel
npm install
npm run build
```

Then activate the plugin in WordPress. The compiled files in `build/` are what WordPress loads.

## Development

```bash
npm start              # Build and watch for changes
npm run build          # Production build
npm run lint:js        # Lint JavaScript
npm run lint:css       # Lint styles
npm run plugin-zip     # Create an installable zip
```

PHP coding standards (requires `composer install` first):

```bash
npm run lint:php       # phpcs
npm run lint:php:fix   # phpcbf
```

phpcs only checks PHP files (see `phpcs.xml.dist`); JavaScript and styles are linted by `wp-scripts`. All three linters currently pass without errors, so keep it that way: run them before committing.

### Translations

Translations ship with the plugin in `languages/` (currently Danish, `da_DK`), because WordPress.org doesn't provide them for a plugin that isn't in its directory. For PHP strings (front end, block titles), a translation in `wp-content/languages/plugins/` takes precedence; the editor JavaScript always uses the JSON files here.

After changing strings, run `npm run build` first (the template is read from `build/`, so the editor's JSON files match the built scripts), then update with WP-CLI (`studio wp` on a WordPress Studio site):

```bash
wp i18n make-pot . languages/gopublish-carousel.pot --exclude=node_modules,vendor,src
wp i18n update-po languages/gopublish-carousel.pot languages
# Translate the new strings in languages/gopublish-carousel-da_DK.po, then:
wp i18n make-mo languages
wp i18n make-json languages --no-purge
```

`--no-purge` keeps the JavaScript strings in the `.po`; the `.mo` and JSON files are generated, so don't edit them by hand.

### How it works

- **Registration:** `npm run build` generates `build/blocks-manifest.php` (`--blocks-manifest`), and `wp_register_block_types_from_metadata_collection()` registers every block in it. A new block folder in `src/` is registered automatically. Settings that `block.json` can't express go through the `register_block_type_args` filter.
- **Rendering:** the carousel is a dynamic block registered with `skip_inner_blocks`. `render.php` renders each slide once with `gopublish_carousel_render_inner_block()`, which applies the same filters and block context as core. The output is the navigation, a live region and the slides in a scroll area (`.carousel-track`). A carousel without slides renders nothing.
- **Scrolling:** `.carousel-track` is a native scroll area (`overflow-x: auto`, `scroll-snap-type: x mandatory`, hidden scrollbar). The slide width is computed in CSS from `--columns`, `--carousel-gap` and the cutoff effect, and small screens use `--mobile-width`. The browser handles touch, trackpad, keyboard scrolling and snapping.
- **State:** each carousel's settings and state live in its `data-wp-context`: `canScroll`, `atStart`, `atEnd`, the buttons' disabled flags and the announcement. The server renders a best guess, and directives (`data-wp-bind--hidden`, `data-wp-bind--aria-disabled`, `data-wp-class--is-*`) are applied by WordPress when rendering, so the HTML is right before any JavaScript runs. One store, `gopublish-carousel` in `view.js`, handles every carousel on the page: it re-measures on load, on `scrollend` (with a short debounce in browsers without it) and when the scroll area is resized.
- **Buttons and rewind:** the buttons call `scrollBy()` by *Slides to scroll* × (slide width + gap). At an end, they `scrollTo()` the other end when *Rewind at the end* is on, and do nothing otherwise. In right-to-left text, the direction is reversed.
- **Gap:** Block spacing (`style.spacing.blockGap`) becomes `--carousel-gap`, validated by `gopublish_carousel_gap_value()`. Core only outputs blockGap for blocks with layout support, so the carousel adds per-viewport values itself (WordPress 7.1): carousels with the same values share a class, and `gopublish_carousel_add_viewport_gap_styles()` adds `!important` rules with core's viewport media queries to the block's stylesheet with `wp_add_inline_style()`. (Not the style engine's block-supports store: with the Gutenberg plugin active, rules added to core's store aren't printed.)
- **Breakpoint:** small screens are everything below core's `@desktop` viewport (theme.json `settings.viewport`, default 782px). `gopublish_carousel_small_screen_query()` builds the media query with `WP_Theme_JSON::get_viewport_media_queries()`, and the small-screen CSS is generated in PHP and attached to the block's stylesheet.
- **Editor:** `edit.js` uses the front-end classes (`.carousel-container`, `.carousel-track`, `columns-N`, `cutoff`) and sets `--columns`, `--mobile-width` and `--carousel-gap`, so `style.scss` and the small-screen CSS apply in the editor too. Per-viewport gaps are written to a `<style>` element with the same media queries as the front end, which PHP passes to the editor as `window.gopublishCarousel.mediaQueries`. Slides get an editor-only `carousel-slide` class. `editor.scss` only softens snapping while editing and adds the "Show all slides" grid. The arrows scroll the row with plain React, following the same rewind setting.
- **Starting slides:** a default block variation (in `index.js`) inserts three slides. It replaces the InnerBlocks `template` prop, which is deprecated in newer editor versions.

### Accessibility

- **Semantics:** the wrapper has `aria-roledescription="carousel"`, and is a `region` when the *Carousel label* setting (`ariaLabel` attribute, Advanced panel) is filled in, otherwise a `group`. Each slide is a `group` with `aria-roledescription="slide"` and a label such as "2 of 9".
- **Navigation:** the buttons have translatable `aria-label`s and `aria-controls`, and a `:focus-visible` style. With *Rewind at the end* off, they get `aria-disabled="true"` at the ends (not `disabled`, so they keep focus). On small touch screens they're visually hidden (not removed) until keyboard focus enters the carousel.
- **Keyboard:** all slides stay in the tab order, and the browser scrolls a focused element into view. A scroll area must be reachable by keyboard: when no slide contains anything focusable (`gopublish_carousel_has_focusable_content()`), `.carousel-track` gets `tabindex="0"` and a focus ring, and the arrow keys scroll it.
- **Announcements:** a visually hidden `aria-live="polite"` region, bound with `data-wp-text`, announces the fully visible slides after a button scroll ("Slide 3 of 9" or "Slides 3 to 5 of 9"). Swiping, scrolling and tabbing don't announce anything: when focus moves into a slide, screen readers already read its label. The text templates are translated in PHP and passed in the context.
- **Reduced motion:** with `prefers-reduced-motion: reduce`, `scroll-behavior` is `auto`, so button scrolls and rewinds jump instead of animating.

### Styling

The carousel is styled with CSS custom properties on `.wp-block-gopublish-carousel`, for example:

```css
.wp-block-gopublish-carousel {
	--nav-button-background-hover: #1e1e1e;
	--nav-container-justify-content: center;
}
```

The full list is in the FAQ in [readme.txt](readme.txt). The wrapper also has state classes for styling: `is-scrollable`, `is-at-start` and `is-at-end`.
