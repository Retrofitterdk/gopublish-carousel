# Go:Publish Carousel

A carousel block for WordPress. Each slide can hold any blocks. The carousel is rendered on the server and built on native scrolling (CSS scroll snap), with a small script on the [Interactivity API](https://developer.wordpress.org/block-editor/reference-guides/interactivity-api/) for the buttons. No jQuery or third-party slider library.

- **Requires:** WordPress 6.8+, PHP 7.2+
- **License:** GPL-2.0-or-later
- **Changelog and user FAQ:** see [readme.txt](readme.txt)

## Features

- Built from parts, each its own block: Carousel Slides (the row of slides, each a Carousel Slide that can contain any blocks), Carousel Navigation (Previous/Next) and Carousel Pagination (dots). Navigation and Pagination can be placed above or below the slides, justified and set to content, wide or full width.
- 1–6 slides visible at once, with a configurable number of slides to scroll.
- Optional cutoff effect: the last visible slide is partly shown (with one column, the next one peeks in).
- Columns, cutoff and slides to scroll per screen size (desktop, tablet, mobile), following core's viewports.
- Native scrolling: swipe, trackpad, keyboard and momentum are handled by the browser, snapping to the start of a slide.
- Previous/next buttons, with optional rewinding at the ends (*Rewind at the end*), and pagination dots (one per position the buttons reach).
- Navigation and pagination are hidden when all slides fit in view.
- Block spacing sets the gap between slides, per viewport in WordPress 7.1.
- Right-to-left support.
- The editor shows the carousel as on the front end (one scrollable row with the real widths, gap, arrows and dots), with "Add to carousel", "Add slide" and a "Show all slides" grid view in the toolbars.
- Wide/full alignment, spacing and minimum height support.
- Accessible, following the [W3C carousel pattern](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/) (see below).
- Translation-ready; Danish included.

## Installation

**From a zip:** upload it under Plugins → Add New → Upload Plugin, then activate it.

**From source:**

```bash
git clone https://github.com/Retrofitterdk/gopublish-carousel.git
cd gopublish-carousel
npm install
npm run build
```

Then activate the plugin in WordPress. The compiled files in `build/` are what WordPress loads.

## Development

```bash
npm start              # Build and watch for changes
npm run build          # Production build
npm run lint:js        # Lint JavaScript
npm run lint:css       # Lint styles
npm run plugin-zip     # Create an installable zip
```

PHP coding standards (requires `composer install` first):

```bash
npm run lint:php       # phpcs
npm run lint:php:fix   # phpcbf
```

phpcs only checks PHP files (see `phpcs.xml.dist`); JavaScript and styles are linted by `wp-scripts`. All three linters currently pass without errors, so keep it that way: run them before committing.

### Translations

Translations ship with the plugin in `languages/` (currently Danish, `da_DK`), because WordPress.org doesn't provide them for a plugin that isn't in its directory. For PHP strings (front end, block titles), a translation in `wp-content/languages/plugins/` takes precedence; the editor JavaScript always uses the JSON files here.

After changing strings, run `npm run build` first (the template is read from `build/`, so the editor's JSON files match the built scripts), then update with WP-CLI (`studio wp` on a WordPress Studio site):

```bash
wp i18n make-pot . languages/gopublish-carousel.pot --exclude=node_modules,vendor,src
wp i18n update-po languages/gopublish-carousel.pot languages
# Translate the new strings in languages/gopublish-carousel-da_DK.po, then:
wp i18n make-mo languages
wp i18n make-json languages --no-purge
```

`--no-purge` keeps the JavaScript strings in the `.po`; the `.mo` and JSON files are generated, so don't edit them by hand.

```
gopublish-carousel.php     Plugin bootstrap: block registration, translations, viewport/gap CSS and render helpers
src/carousel/              Carousel block (dynamic: render.php + view.js, shared modules)
src/carousel-slides/       Carousel Slides block (the scroll area; only inside a Carousel)
src/carousel-slide/        Carousel Slide block (static wrapper; only inside Carousel Slides)
src/carousel-navigation/   Carousel Navigation block (Previous/Next; only inside a Carousel)
src/carousel-pagination/   Carousel Pagination block (dots; only inside a Carousel)
build/                     Compiled output (generated by npm run build)
```

See [src/README.md](src/README.md) for what each source file does.

### How it works

- **Registration:** `npm run build` generates `build/blocks-manifest.php` (`--blocks-manifest`), and `wp_register_block_types_from_metadata_collection()` registers every block in it. A new block folder in `src/` is registered automatically. Settings that `block.json` can't express go through the `register_block_type_args` filter.
- **Blocks:** Carousel → Carousel Navigation, Carousel Slides → Carousel Slide …, Carousel Pagination. The Carousel holds the settings, the Interactivity context and the live region; the parts are inside it (`parent`), one of each (an editor filter, `blockEditor.__unstableCanInsertBlockType` in `index.js`, because a block's `parent` overrides the parent's allowed-blocks list). Navigation and Pagination use core's flex layout support for justification only, and `align` for their width; the Carousel offers them wide/full through the `layout` option of its `useInnerBlocksProps`, as it has no layout support itself.
- **Rendering:** the Carousel and Carousel Slides are dynamic blocks registered with `skip_inner_blocks`. The Carousel renders Carousel Slides first (any further ones are skipped), reads the number of slides from it (`data-carousel-items`, `gopublish_carousel_count_slides()`), then the other parts, passing the slides' ID and count through the block context. Each part is rendered with `gopublish_carousel_render_inner_block()`, which applies the same filters and block context as core; `gopublish_carousel_render_slides()` and `gopublish_carousel_render_navigation()` produce the markup. A carousel without slides renders nothing.
- **Before 0.5.0:** the slides were the Carousel's own inner blocks and the Carousel rendered the navigation itself. `render.php` still renders that structure the same way; in the editor, a block deprecation (`isEligible` + `migrate` in `index.js`) converts it to Navigation (full width) + Carousel Slides.
- **Scrolling:** `.carousel-track` is a native scroll area (`overflow-x: auto`, `scroll-snap-type: x mandatory`, hidden scrollbar). The slide width is computed in CSS from `--visible`, `--gaps` and `--carousel-gap` (see Layouts). The browser handles touch, trackpad, keyboard scrolling and snapping.
- **Layouts:** `columns`, `cutoff` and `scroll` are the base layout; the `viewports` attribute overrides them per viewport (`{"@tablet": {"columns": 2}, "@mobile": {"columns": 1}}`), mobile inheriting from tablet and tablet from the base. `gopublish_carousel_layouts()` (PHP) and `getLayouts()` in `layouts.js` (editor) resolve this identically, and turn each layout into `--columns`, `--cutoff-trim` / `--cutoff-peek` (0 or 1: the cutoff effect trims the last slide with 2+ columns, or lets the next one peek in with 1 column) and `--slides-to-scroll`. `style.scss` computes `--visible` and `--gaps` from them and `--cutoff-amount` (default 0.3, themeable), e.g. 2.7 slides for 3 columns with cutoff and 1.3 for 1 column. The base goes in the inline style, the viewports into per-viewport rules with core's media queries (falling back to core's default breakpoints before WordPress 7.1). Carousels without `viewports` (from before 0.4.0) get tablet min(2, columns) and mobile 1, both with cutoff, and no cutoff at 1 column on desktop, as before.
- **State:** each carousel's settings and state live in its `data-wp-context`: `canScroll`, `atStart`, `atEnd`, the buttons' disabled flags, the announcement and, with a Pagination, a `dots` list (current, hidden, label per dot) that each dot binds to (`context.dots.N.current`). The server renders a best guess, and directives (`data-wp-bind--hidden`, `data-wp-bind--aria-disabled`, `data-wp-class--is-*`) are applied by WordPress when rendering, so the HTML is right before any JavaScript runs. One store, `gopublish-carousel` in `view.js`, handles every carousel on the page: it re-measures on load, on `scrollend` (with a short debounce in browsers without it) and when the scroll area is resized.
- **Pages:** `pages.js` (shared by `view.js` and the editor) works out the pagination: the scroll positions (slides that can be first in view), the pages the buttons reach (every *Slides to scroll*, plus the end) and the current page. A dot is rendered per slide, the most pages any layout can have; the ones the current layout doesn't need are hidden.
- **Buttons and rewind:** the buttons call `scrollBy()` by `--slides-to-scroll` (read from the computed CSS, so it follows the current viewport) × (slide width + gap). At an end, they `scrollTo()` the other end when *Rewind at the end* is on, and do nothing otherwise. In right-to-left text, the direction is reversed.
- **Gap:** Block spacing (`style.spacing.blockGap`) becomes `--carousel-gap`, validated by `gopublish_carousel_gap_value()`. Core only outputs blockGap for blocks with layout support, so the carousel adds per-viewport values itself (WordPress 7.1): carousels with the same values share a class, and `gopublish_carousel_add_viewport_styles()` adds `!important` rules (together with the per-viewport layouts) with core's viewport media queries to the block's stylesheet with `wp_add_inline_style()`. (Not the style engine's block-supports store: with the Gutenberg plugin active, rules added to core's store aren't printed.)
- **Breakpoint:** small screens are everything below core's `@desktop` viewport (theme.json `settings.viewport`, default 782px). `gopublish_carousel_small_screen_query()` builds the media query with `WP_Theme_JSON::get_viewport_media_queries()`, and the small-screen CSS is generated in PHP and attached to the block's stylesheet.
- **Editor:** the Carousel's `edit.js` uses the front-end classes (`.carousel-container`, `.carousel-track`, `columns-N`, `cutoff`) and sets the base layout properties and `--carousel-gap`, so `style.scss` and the small-screen CSS apply in the editor too. Per-viewport layouts and gaps are written to a `<style>` element with the same media queries as the front end, which PHP passes to the editor as `window.gopublishCarousel.mediaQueries`. Slides get an editor-only `carousel-slide` class. `editor.scss` only softens snapping while editing and adds the "Show all slides" grid. Navigation and Pagination find the scroll area through the DOM and measure it with `use-carousel-track.js`, and scroll it with plain React, following the same rewind setting; they add the layout support's classes themselves (`useBlockEditContext()`), because the editor only adds them to blocks with inner blocks. "Add to carousel" (Carousel toolbar) adds a slide, Navigation or Pagination; "Add slide" and "Show all slides" are on Carousel Slides. The Layout panel's Screen size switch is tied to the editor's device preview (`core/editor` `getDeviceType`/`setDeviceType`); it uses `__experimentalToggleGroupControl`, because WordPress 7.1 doesn't ship the stable name yet. An old carousel's layout is written out on its first layout change, so it doesn't jump.
- **Starting blocks:** a default block variation (in `index.js`) inserts Navigation, Carousel Slides with three slides, and Pagination. It replaces the InnerBlocks `template` prop, which is deprecated in newer editor versions.

### Accessibility

- **Semantics:** the wrapper has `aria-roledescription="carousel"`, and is a `region` when the *Carousel label* setting (`ariaLabel` attribute, Advanced panel) is filled in, otherwise a `group`. Each slide is a `group` with `aria-roledescription="slide"` and a label such as "2 of 9".
- **Navigation:** the buttons have translatable `aria-label`s and `aria-controls`, and a `:focus-visible` style. With *Rewind at the end* off, they get `aria-disabled="true"` at the ends (not `disabled`, so they keep focus). On small touch screens they're visually hidden (not removed) until keyboard focus enters the carousel.
- **Keyboard:** all slides stay in the tab order, and the browser scrolls a focused element into view. A scroll area must be reachable by keyboard: when no slide contains anything focusable (`gopublish_carousel_has_focusable_content()`), `.carousel-track` gets `tabindex="0"` and a focus ring, and the arrow keys scroll it.
- **Pagination:** a `group` labelled "Choose slide" of buttons labelled "Go to slide N", the current one with `aria-current="true"`, all with `aria-controls`. Each is 24 × 24 px (WCAG target size) with a smaller dot drawn inside.
- **Announcements:** a visually hidden `aria-live="polite"` region, bound with `data-wp-text`, announces the fully visible slides after a button or dot scroll ("Slide 3 of 9" or "Slides 3 to 5 of 9"). Swiping, scrolling and tabbing don't announce anything: when focus moves into a slide, screen readers already read its label. The text templates are translated in PHP and passed in the context.
- **Reduced motion:** with `prefers-reduced-motion: reduce`, `scroll-behavior` is `auto`, so button scrolls and rewinds jump instead of animating.

### Styling

The carousel is styled with CSS custom properties on `.wp-block-gopublish-carousel`, for example:

```css
.wp-block-gopublish-carousel {
	--nav-button-background-hover: #1e1e1e;
	--pagination-dot-color: #1e1e1e;
}
```

The full list is in the FAQ in [readme.txt](readme.txt). The navigation's icon comes from WordPress's icon registry (7.1+, `icon` attribute, rendered with `wp_get_icon()`; the editor's picker reads the same icons as core's Icon block through the REST API), drawn as is for Next and mirrored for Previous, or the other way round for icons whose name says they point back (`left`, `previous`, `back`: the `has-backward-icon` class, `gopublish_carousel_icon_points_back()`); without a registry or a registered icon, the plugin's own arrow is used. Icons are coloured through `color` (they use `currentColor`, filled or stroked) and sized with `--nav-button-icon-size`. The buttons' colours are the block's own attributes (`iconColor`, `buttonColor` and their `…HoverColor` versions, each with a `custom…` attribute for custom colours; a Color panel built with `PanelColorSettings` and `withColors`), not the Color support, whose text colour WordPress shows under Typography. Borders use the Border support with serialization skipped. `gopublish_carousel_navigation_button_styles()` (mirrored by `src/carousel-navigation/button-styles.js` in the editor) turns both into the buttons' `--nav-button-*` custom properties on the wrapper, so the hover and focus rules in style.scss keep working. Global border styles for the block don't reach the buttons. Button padding (`buttonPadding`, per side, a spacing preset or size, edited with the spacing sizes control) and Icon size (`iconSize`, pixels) are own attributes too, added to the Dimensions panel with `ToolsPanelItem`; the button is sized by its content (icon plus padding) with `--nav-button-width`/`--nav-button-height` as minimum. Justification and width of the navigation and pagination are block settings; the gap between buttons and dots (`--nav-container-gap`, `--pagination-gap`) is only a custom property, because core's default gap for flex layouts would otherwise override it. The wrapper also has state classes for styling: `is-scrollable`, `is-at-start` and `is-at-end`.
